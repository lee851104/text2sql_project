# GridLens TW 系統卡

## 用途

GridLens TW 將中文問題轉成限定範圍的唯讀 SQL，用於探索台電開放資料中的每日系統尖峰指標、尖峰時刻機組出力、機組主檔、歲修事件與年度發電成本。

## 可回答範圍

- 資料涵蓋期內的單日尖峰負載、備轉容量與備轉容量率。
- 機組或機組彙總欄位在每日系統尖峰時刻的瞬時出力。
- 台電自有水力與火力機組的電廠、縣市、燃料、裝置容量與商轉日期。
- 2023～2025 年各發電方式的每度發電成本，並區分審定決算與自編決算。
- 台電自建再生能源場站 2024-01 起的月發電量與裝置容量，回答一律附涵蓋範圍說明。

## 不適用情境

- 不能將跨日的尖峰瞬時出力相加當成發電量。
- 不能回答未納入的售電電價、碳排或逐時曲線；發電成本只有年度、分發電方式粒度，無法拆到電廠或機組。
- 再生能源發電量只涵蓋台電自建場站（約全國風光地熱的 3～4%），不能回答全國或縣市總量；火力與核能沒有任何發電量資料。
- 核能、IPP、汽電共生與風光彙總缺少同粒度機組主檔，不提供機組級還原。
- 部分電廠同時落在具名欄位與殘差桶，電廠總出力只能附限制揭露。

## 安全邊界

系統只允許查詢審核過的 `v_*` 語意檢視，並必須在執行前通過 SQL 安全與資料語意雙守門。本機 LLM 不是信任邊界，也不能繞過守門存取資料庫。

## 即時資料

- 「資料總覽」頁的即時發電區塊顯示台電 `d006001` 每 10 分鐘的機組發電量，由獨立的收集器寫進 `realtime.db`。查詢中心用「現在、今天、昨天」等用詞問時，改查 `realtime.db` 的 `v_rt_*` 檢視，不與歷史快照混用；每個答案都附資料時間與收集狀態。
- 即時資料**不經過四眼審核**：每一筆快照由自動驗證放行。結構有問題的整份拒收；數值有問題的照收、標記品質，並在頁面上揭露。會改變結果的規則，也就是解析程式、`taipower_align/realtime_units.csv` 的人工決定與 `configs/realtime.yaml`，變更時才走 PR 審查。
- 面板只加總狀態「正常」的值。資料可能落後或中斷，頁面會標出資料時間與落後分鐘數，不能作為供電或調度決策依據。
- 權限與查詢一致：電廠帳號只看到自己電廠的機組與跨廠共用的列，歸屬未定的機組看不到。
- 即時發電量是 10 分鐘瞬間淨出力的估算（加總 ÷ 6），不是電表讀數；只從收集器第一次執行那天開始，缺口（收集器沒在跑、抓取失敗、通訊異常）不補 0，以資料完整度揭露。
- 收集器啟動以前的日子可以用台電 `d006010` 回補（每月更新、晚約四個月）。它只有台電自有與部分機組，類型合計不是全國數字，答案會揭露；與即時收集之間的空檔補不回來。
